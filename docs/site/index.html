psi-briefing

Briefings you can read without a meeting.

Text-dense 16:9 slides in a single, self-contained HTML file. A briefing is what you send to the people who could not attend, so the deck has to carry itself.

Slides for a talk you will actually deliver are a different problem, and a different tool: psi-slides turns one Markdown source into a projection, a presenter cockpit, a reading document and a handout. The line between the two is whether anyone is speaking.

You write a document; it picks the layout

The component is chosen from the shape of your text, before anything is rendered. Four blocks of equal rank are four parallel points, so they become a bordered grid; a quotation is the takeaway, so it becomes the band at the bottom.

How you write one

A Markdown file and one command. The output is ordinary readable HTML, so you can hand-tune any slide afterwards.

node tools/md-to-deck.mjs deck.md -o deck.html
python3 -m http.server 8000        # then look at it

tools/build-deck.sh deck.html      # one file you can send

The converter prints a report: which rule fired on each slide, how full its content row is, what it corrected by itself, and which slides are thin in a way no tool can fix. It will rearrange content and split a slide. It will not stretch a container to close a gap, because that was measured and it made the deck worse while improving the score.

Two ideas do the work

Container-query scaling

Every slide is a 16:9 box with container-type: size. Everything inside is measured in cqw and cqh – never px, never rem.

So the layout scales proportionally with the slide. Not pixel-perfect: proportion-perfect, which is what holds a deck together on a laptop and a 4K projector alike.

Semantic design tokens

Every colour and face is a custom property with a meaning rather than a value: --accent, --ink, --highlight.

A theme is a :root{} override and nothing else. The generated SVG charts read the same tokens as they draw, so re-skinning a deck is one file.

When not to use it

It fits content that is already document-shaped: a retrospective, project documentation, a research summary, lecture notes, a report with numbers in it. Those arrive with sections and comparisons to arrange densely, and arranging them densely is the whole job.

It is a poor fit for a sparse performance talk – a keynote driven by timing, delivery and question-then-answer beats. This was tried on a real one and it resisted both treatments: forced into dense slides it fought the dramaturgy, made sparse it produced empty frames. The dramaturgy lives in the speaking, and a deck built to be read cannot hold it.

There is also no animation model beyond click-to-reveal panels, and no speaker view. For either, use psi-slides.
