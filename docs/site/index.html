psi-briefing

A generator for briefing decks.

Write one Markdown file, run one command, and get 16:9 slides in a single self-contained HTML file. Dense enough to read without anyone presenting them, because a briefing is what you send to the people who could not attend.

node tools/md-to-deck.mjs deck.md -o deck.html

For a talk you will actually deliver, use psi-slides instead: one Markdown source, and out come a projection, a presenter cockpit, a reading document and a handout. The line between the two is whether anyone is speaking.

Some readers would rather have slides

A report and a deck can carry the same argument, and which one lands better is a preference rather than a ranking. Some people read a running document and take it in. Others want the same content in frames they can scan, step through and come back to. Neither format is the better one. What matters is that the reader gets the version they will actually read.

The first deck of this kind was a report from the Chair of Privacy and Security in Information Systems on a student-orientation portal it had built, written to be read rather than presented. It is online as Werkstattbericht Studienstart, in German only. psi-briefing is the layout machinery taken out of it.

Writing the document version is cheap, because you write it. Producing the deck usually is not, because somebody places boxes. This tool exists so that the second one costs about what the first one costs.

Convention over configuration

It is quick because it decides most things for you. You set no widths, place no boxes and fill in no template: the structure of your Markdown picks the component for each slide, and the defaults are set so that ordinary cases come out well with nothing specified.

What you give up is fine control. If one panel has to be exactly two centimetres narrower than its neighbour, this is the wrong tool and Keynote is the right one. Most decks never need it, and the ones that do are easier to build by hand than to describe.

An assistant can finish it, because the output is HTML

The file the converter writes is ordinary HTML with named classes, so adjusting one slide by hand means editing one element. That also makes it something you can hand to an LLM directly, with nothing to export or convert first. The repository ships a Claude Code skill as well, so an assistant can build the deck from your notes and then check it against the same rules a person would.

You write a document; it picks the layout

The converter reads how your Markdown is arranged and picks the component from that. Four headings at the same level become a bordered grid, because they are four points of equal weight. A quotation becomes the band across the bottom, because that is where a slide's conclusion goes.

Getting started

Clone the repository and run the converter. Node 18 or newer is the only thing it needs.

git clone https://github.com/UBA-PSI/psi-briefing.git
cd psi-briefing
node tools/md-to-deck.mjs my-deck.md -o my-deck.html
python3 -m http.server 8000        # then look at it

There is no package to install, no lockfile and no release archive to download. That last one is deliberate: the deck you build is the thing you distribute, and it carries no trace of the tool that made it. When you want that single file, the build step folds the stylesheet, the script and the images in, then checks that nothing is left pointing outward:

$ tools/build-deck.sh examples/example-deck.html -o /tmp/deck.html
3/3  verify       checking for anything still external

built   /tmp/deck.html
        0.02 MB linked  ->  0.13 MB self-contained
        no external references: opens with no server and no network

One check this cannot do without a browser: open the file and confirm
  performance.getEntriesByType('resource').filter(e => !e.name.startsWith('data:'))
is empty, and that no image is broken.

That last check comes out empty on this page as well. The two screenshots above and the favicon are data: URIs, so the browser fetched nothing to show you this page but the page itself.

How you write one

A Markdown file and one command. The output is ordinary readable HTML, so you can hand-tune any slide afterwards.

node tools/md-to-deck.mjs deck.md -o deck.html
python3 -m http.server 8000        # then look at it

tools/build-deck.sh deck.html      # one file you can send

What you get back

The deck, and a report of which rule fired on each slide. This is the run for the example deck; the Markdown reference says what each rule needs and what the percentage measures.

    2   89 %          single panel                        What this file is
    3    –            divider                             How the timeline went
    4  100 %          facts grid (bold numbers)           The numbers
    5~  84 % gap 11 %  timeline from 2-column table        Plan against reality
    6  100 %          directive:chart                     Commits per week
    7    –            divider                             How it was built
    8  100 %          4 cards -> .net grid                Four areas of work
    9   97 %          directive:delta                     What changed for the user
   10   93 %          flow steps (ordered, bold leads)    The weekly rhythm
   11    –            divider                             What we learned
   12~  61 % gap 34 %  directive:principles                Two ways of working
   13~  83 % gap 15 %  directive:editorial                 Three lessons

  estimated median row fill: 93 % (target 85 %)

Then what it fixed by itself, and what it cannot fix for you:

      78 %  2 cards -> two columns            How a commit is counted
       fix   short row (78 %) -> cols--center; balances the gap, does not fill it
  typography: 6 marks normalised
  layout: 1 correction(s) applied

  thin rows - these need content, which no tool can invent.

It rearranges content and splits slides. It will not stretch a container to close a gap: that took one deck from 74 % to 96 % fill and made it worse (§1 of the write-up).

Two ideas do the work

Container-query scaling

Every slide is a 16:9 box with container-type: size. Everything inside is measured in cqw and cqh – never px, never rem.

So the layout scales with the slide instead of being fixed to it. Every gap and every type size keeps its proportion, so the same deck holds up on a 13-inch laptop and on a projector.

Semantic design tokens

Every colour and face is a custom property with a meaning rather than a value: --accent, --ink, --highlight.

A theme is a :root{} override and nothing else. The generated SVG charts read the same tokens as they draw, so re-skinning a deck is one file.

To re-skin a deck you edit one file. Four of its lines, from themes/bamberg.css:

  --accent:      #00457D;
  --highlight:      #FFD300;
  --paper:      #ffffff;
  --ink:        #1a1a1a;

The dark theme that ships with it, themes/midnight.css, sets those same four names to #7aa2f7, #e0af68, #16181f and #e6e8ef, and runs to 50 lines. Copy either one, change the values, and load it after briefing.css.

When not to use it

It fits content that is already document-shaped: a retrospective, project documentation, a research summary, lecture notes, a report with numbers in it. Those already arrive with sections, comparisons and numbers in an order somebody chose.

It is a poor fit for a sparse spoken talk, the kind that runs on timing and on setting up a question before answering it. A conference keynote was built this way once and resisted both treatments: dense, the slides argued with the talk; sparse, they were empty frames with one sentence on them. The argument was in what the speaker said, and slides meant to be read on their own could not carry it.

There is also no animation model beyond click-to-reveal panels, and no speaker view. For either, use psi-slides.

iA Presenter, in particular

iA Presenter does the same kind of thing: it analyses a slide’s content and picks a layout. The difference is the default. There, the document is a script – an ordinary paragraph is what you say, and you indent one to promote it onto the slide, so what the audience sees is the exception you opt into. Here there is no speaker and nothing to demote: everything is on a slide, and the converter asks how the content is arranged rather than which part of it to show.

Which makes iA Presenter the closer relative of psi-slides, not of this. If you are going to stand up and talk, it is a mature, well-designed product and this is not a serious competitor to it.
