psi-briefing

Briefings you can read without a meeting.

A dependency-free framework for text-dense 16:9 slides meant to be read — the whole deck is one self-contained HTML file that works offline, with no server, no build step and nothing to install.

The genre is the one Nancy Duarte calls Slidedocs® — a document that happens to be shaped like slides, and that carries its argument without a presenter standing next to it.

1See it

The demo is not a screenshot of the artefact. It is the artefact.

Open the example deck → Download the single file

One .html file, ~130 kB, fonts and styles and runtime all inside it. Save it, pull the network cable, double-click it: same deck. Mail it to somebody and they get the whole thing, not a link that rots.

Arrow keys or swipe to move; ? for the keys. Built on this site from examples/example-deck.md on every push, so what you are reading is never older than the source.

While you are authoring you would rather not re-inline on every save, so a deck can link its assets instead — that mode is here too: the hand-built deck with linked CSS and JS. One command folds it into the file above.

2How you write one

You write Markdown. The converter reads the shape of what you wrote and infers the layout — because the shape already carries the meaning. Four ### blocks under a slide are four peers, so they become a bordered 2×2 grid. A > blockquote is the takeaway, so it becomes the highlighted band pinned to the bottom.

Then one command:

node tools/md-to-deck.mjs deck.md -o deck.html

It also reports, per slide, how much of the frame the content actually fills — the failure mode of this genre is a thin slide, and a number is harder to argue with than a feeling. When you want the shareable single file, tools/build-deck.sh deck.html inlines everything and then verifies that nothing external survived.

3The two ideas that do the work

Container-query scaling

Every slide is a 16:9 box with container-type: size. Everything inside it — type, spacing, rules, charts — is measured in cqw and cqh, 1% of the slide's width and height. Never px, never rem.

So the layout is not pixel-fixed, it is proportion-perfect: identical on a 13″ laptop, a 4K projector, and a phone held sideways. There is no responsive breakpoint work to do, because there is nothing to break.

Semantic design tokens

Every colour and face is a custom property with a meaning rather than a value: --accent, --ink, --highlight, --font-display.

A theme is therefore nothing but a :root { … } override — one file, no component touched. The SVG charts the runtime draws read the same tokens at draw time, so they re-skin with everything else instead of drifting out of palette.

4When not to use it

This framework is a poor fit for a sparse performance talk — a short spoken keynote driven by timing, delivery, and question→answer beats. Forcing that talk into dense slides fights its dramaturgy; stripping the slides bare just yields empty ones. It shines where the source is already document-shaped: retrospectives, project documentation, research summaries, whitepapers, lecture notes, data-driven reports.

If you are giving a talk rather than sending a document, use the sibling project instead: psi-slides is the spoken medium — one Markdown source producing a projection, a presenter cockpit, a reading document and a handout.
